01 · Contexto de Ejecución

Contexto de Ejecución

Todo lo que JavaScript hace —variables, funciones, this— ocurre dentro de un contexto. Esta es la base de todo lo demás.

Cuando JavaScript ejecuta tu código, no lo hace en el vacío. Cada porción de código corre dentro de un contexto de ejecución: el entorno que define qué variables existen, qué funciones se pueden llamar y —lo más importante para esta lección— quién es this.

Cada vez que llamas a una función se crea un contexto nuevo. Y desde el primer instante existe un contexto global: el hogar del código que está fuera de cualquier función.

El call stack: una pila de contextos

JavaScript lleva la cuenta de los contextos activos con una estructura llamada pila de llamadas (call stack). Funciona como una pila de platos: el último que entra es el primero que sale (LIFO, del inglés last in, first out). Cuando una función termina, su contexto se destruye y el control vuelve al contexto anterior.

Pruébalo: ejecución paso a paso

Este es el corazón de la lección. Pulsa Ejecutar paso a paso y observa cómo se crean y se destruyen los contextos. A la derecha tienes la pila; la línea de código resaltada te dice qué se está ejecutando en cada momento.

El código que vamos a ejecutar

function saludar(nombre) {
  console.log("Hola " + nombre);
}
function main() {
  saludar("Ana");
}
main();

Pila de llamadas

Dos fases: creación y ejecución

Cada contexto nace en dos fases. Entenderlas explica los comportamientos más extraños de JavaScript (como el hoisting, que verás a continuación):

Las dos fases de un contexto de ejecución
Fase Qué ocurre
Creación Se crea el scope: las variables y las funciones se registran. Hay hoisting de var (inicializada con undefined) y de las declaraciones de función. let/const también hoistean, pero sin inicialización: están en la zona muerta temporal (TDZ) hasta que su línea corre; usarlas antes lanza un ReferenceError. Se define this del contexto.
Ejecución Se asignan los valores (var x = 1). El código se ejecuta línea por línea, de arriba hacia abajo.

Hoisting: las declaraciones se adelantan

// Fase de creación: "despedida" existe (hoisting de var),
// pero todavía no tiene valor.
console.log(despedida); // → undefined

// Las declaraciones de función se suben completas:
// saludar() ya se puede llamar aquí.
saludar(); // → "Hola"

var despedida = "Chau"; // la asignación espera a la fase de ejecución

function saludar() {
  console.log("Hola");
}
// var hoistea e inicializa con undefined...
console.log(despedida); // → undefined — var existe (hoisting)
console.log(apodo); // → ReferenceError — let está en la TDZ
var despedida = "Chau";
let apodo = "Anita";

Pégalo en la consola de tu navegador o en Node.

En la fase de creación, JavaScript «sube» (hoisting) las declaraciones de var y las declaraciones de función al principio de su contexto. Las asignaciones, en cambio, esperan a la fase de ejecución.

Por eso console.log(despedida) no lanza un error: la variable ya existe (vale undefined). Y por eso saludar() funciona antes de su definición: la función completa ya fue registrada.

var hoistea e inicializa con undefined; let y const también hoistean, pero no se inicializan: viven en la zona muerta temporal (TDZ) hasta que su línea se ejecuta. Usarlas antes lanza un ReferenceError.

Un consejo: escribe las declaraciones arriba por legibilidad, pero ahora ya sabes por qué JavaScript no te lo exige.

El modo estricto existe para lo mismo: convertir errores silenciosos (como las globales implícitas) en errores visibles. Y la zona muerta temporal hace lo propio con let/const: usar una variable antes de su declaración no falla en silencio, lanza un ReferenceError. Ver sección 03 →

Trampa clásica

Contexto ≠ scope. El contexto responde «¿dónde se ejecuta y quién es this?». El scope responde «¿qué variables son visibles?». Son dos preguntas distintas: confundirlas es el error típico de quien empieza.

02 · this y las 4 reglas

this y las 4 reglas

La llamada: this es quien contesta. Cambia a quién llamas, cambia quién contesta.

this es el objeto dueño del contexto de ejecución actual. No es la función. No es el scope. Es el objeto que «recibe» la llamada.

Piensa en una llamada telefónica: cuando escribes ana.saludar(), es como llamar al teléfono de ana — y quien contesta es ana. this es siempre quien contesta la llamada. No importa dónde se definió la función: importa a quién llamaste. En cada ejemplo de abajo, el haz te muestra quién contesta. La pregunta no es «¿qué es this?» sino «¿a quién le llamaste?».

Regla 1

Por defecto

Una llamada suelta, sin objeto delante: foo().

function foo() {
  console.log(this);
}
foo(); // window (normal) · undefined (estricto)

Pégalo en la consola de tu navegador o en Node.

¿Quién es this?

contesta la centralita global — window en modo normal · undefined en modo estricto

contesta: window / nadie (undefined)
Regla 2

Implícita

Llamada de método: el objeto va a la izquierda del punto.

const ana = { nombre: "Ana", saludar: function () { console.log(this.nombre); } };
ana.saludar(); // "Ana" — this = ana

Pégalo en la consola de tu navegador o en Node.

¿Quién es this?

contesta el objeto a la izquierda del punto

contesta: ana
Regla 3

Explícita

Forzada con call, apply o bind: tú decides quién es this. 

function foo() { console.log(this.nombre); }
const objeto = { nombre: "objeto" };
foo.call(objeto); // "objeto"
foo.apply(objeto, [1, 2]); // "objeto"
const fija = foo.bind(objeto);
fija(); // "objeto"

Pégalo en la consola de tu navegador o en Node.

¿Quién es this?

contesta el objeto que pasas como primer argumento

contesta: el objeto que pasas
Regla 4

Con new

Con new delante, la función crea un objeto nuevo y this apunta a él.

function Persona(nombre) {
  this.nombre = nombre;
}
const ana = new Persona("Ana");
console.log(ana.nombre); // "Ana"

Pégalo en la consola de tu navegador o en Node.

¿Quién es this?

contesta la instancia nueva que acaba de crear new

contesta: la instancia nueva

Prioridad · ¿cuál gana?

Si dos reglas se pelean, gana siempre la de mayor jerarquía: new > explícita > implícita > por defecto. Ejemplo: en objeto.metodo.call(otro) hay llamada de método (implícita) y call (explícita). Gana la explícita: suena el teléfono de otro.

03 · Modo estricto vs normal

Modo estricto vs normal

El modo estricto es JavaScript con el volumen al máximo: los errores silenciosos se vuelven ruidosos.

El modo estricto es una versión más rigurosa de JavaScript. Se activa escribiendo "use strict"; al principio de un script o de una función. En modo normal, JavaScript «perdona» muchos errores en silencio; en modo estricto, esos mismos errores lanzan excepciones.

Mira el mismo código en ambos modos. Cambia solo una cosa: this en una llamada suelta.

Modo normal

function mostrarThis() {
  console.log(this);
}
mostrarThis();

Modo estricto

¿Por qué importa?

En modo normal, si asignas una variable sin declararla, JavaScript crea una variable global en silencio: contador = 1 contamina window y puede chocar con otras partes de tu programa.

En modo estricto, ese mismo código lanza un ReferenceError al instante. El error es ruidoso a propósito: mejor que falle ahora, en desarrollo, a que falle en producción a las tres de la mañana.

04 · Puente a la POO

Puente a la POO

¿Y por qué importa todo esto? Porque antes de las clases, la POO en JavaScript se construía con funciones constructoras. Y this es el pegamento.

Antes de ES6 no existía class. La programación orientada a objetos se hacía con funciones constructoras + new + prototype. Observa cómo this conecta la función con el objeto nuevo: 

function Persona(nombre) {
  this.nombre = nombre; // this = la instancia nueva
}

Persona.prototype.saludar = function () {
  console.log("Hola, soy " + this.nombre);
};

const ana = new Persona("Ana");
ana.saludar(); // "Hola, soy Ana"

Pégalo en la consola de tu navegador o en Node.

new Persona("Ana") hace tres cosas: crea un objeto nuevo, lo asigna a this dentro de la función y lo devuelve. Por eso this.nombre = nombre llena la instancia: ana.nombre es "Ana".

Persona.prototype.saludar comparte el método con todas las instancias. Dentro de él, this es la instancia que hizo la llamada: en ana.saludar(), this = ana (regla implícita).

Este es el patrón constructor + prototype que usaba todo JavaScript antes de las clases de ES6. Las clases modernas son azúcar sintáctico sobre esto.

Patrón

new te da el objeto, this te deja llenarlo. La llamada llega al objeto recién creado por new: contesta la instancia nueva.

contesta: ana · nueva instancia de Persona

05 · Clases ES6

Clases ES6: la POO moderna

La sintaxis que empaqueta todo lo pre-ES6 que ya viste: new, prototype y this siguen ahí, con versión de cada pieza.

Las clases de ES6 no traen un motor nuevo: son azúcar sintáctico sobre lo que ya conoces. class empaqueta el patrón constructor + prototype en una sintaxis limpia, y this dentro de un método sigue siendo la instancia (regla con new). Lo único que no es azúcar es #: privacidad real, no la convención _. 

// ===== CLASE BASE — class — ES2015 (ES6) =====
class Persona {
  planeta = "Tierra";            // Campo público — ES2022

  #secreto = "café con leche";   // Campo privado — ES2022

  constructor(nombre, edad) {    // constructor — ES2015 (ES6)
    this.nombre = nombre;
    this.edad = edad;
  }

  saludar() {                    // Método de instancia — ES2015 (ES6)
    return `Hola, soy ${this.nombre}`;
  }

  get secreto() {                // get — ES5 · en clase: ES2015
    return this.#secreto;
  }

  #revelar() {                   // Método privado — ES2022
    return this.#secreto + " por la mañana";
  }

  static crear(nombre) {         // Método estático — ES2015 (ES6)
    return new Persona(nombre, 0);
  }
}

// ===== HERENCIA — extends/super — ES2015 (ES6) =====
class Estudiante extends Persona {
  constructor(nombre, edad, curso) {
    super(nombre, edad);         // constructor de Persona
    this.curso = curso;
  }

  saludar() {                    // Sobrescritura (override)
    return `${super.saludar()} — estudio ${this.curso}`;
  }
}

const ana = new Estudiante("Ana", 25, "JavaScript");
ana.saludar();      // "Hola, soy Ana — estudio JavaScript"
ana.secreto;        // "café con leche" (getter)
ana.#secreto;       // SyntaxError — # es privado de verdad (ES2022)

Pégalo en la consola de tu navegador o en Node.

Todo lo que ya viste con new, prototype y this sigue aquí, con otra sintaxis. new Estudiante("Ana", 25, "JavaScript") crea el objeto, this dentro del constructor es la instancia (regla con new) y los métodos viven en el prototype compartido: la clase es azúcar, el motor es el mismo.

Lo que no es azúcar: #. La privacidad real no es la convención _ — un guion bajo solo avisa, no protege. ana.#secreto lanza SyntaxError al parsear: ni siquiera llega a ejecutarse.

static cuelga el método de la clase, no de la instancia: Persona.crear("Ana"), no ana.crear(). Y extends encadena prototipos: Estudiante hereda de Persona, y super llama al constructor o al método del padre.

Patrón

Clases = azúcar, debajo sigue el motor. new crea el objeto, this = quien contesta (la instancia), métodos en prototype. La clase solo lo empaqueta con sintaxis limpia.

contesta: ana · instancia de Estudiante

Las Arrow Functions y el POO

// ===== ARROW FUNCTIONS Y POO — ES6 (ES2015) =====
class Usuario {
  nombre = "Ana";              // Campo público — ES2022

  saludar() {                  // Método: this = quien llama (implícita)
    return `Hola, soy ${this.nombre}`;
  }

  saludarFlecha = () => {      // Campo con Arrow Function: this = la instancia (léxico)
    return `Hola, soy ${this.nombre}`;
  };
}

const u = new Usuario();

// La ventaja real: pasar el método suelto sin perder this
setTimeout(u.saludar, 1000);        // al ejecutarse, this se perdió → TypeError
setTimeout(u.saludarFlecha, 1000);  // "Hola, soy Ana" — this ya está fijado

const f = u.saludar;               // Método extraído: pierde this
f();                               // TypeError / undefined (regla por defecto)

const g = u.saludarFlecha;         // Arrow Function extraída: conserva this
g();                               // "Hola, soy Ana" (auto-bind)

u.saludarFlecha.call({ nombre: "Beto" });  // "Hola, soy Ana" — call ignorado
new (() => {})                            // TypeError — la Arrow Function no es constructor

Pégalo en la consola de tu navegador o en Node.

La Arrow Function no tiene this propio: lo hereda del ámbito donde nació (léxico). Por eso no sigue las 4 reglas: la llamada no importa. call/apply/ bind se ignoran y new no existe (TypeError).

La ventaja real: podés pasar saludarFlecha suelta — a setTimeout, a un evento, a un .map() — y this sigue siendo la instancia. El método normal solo funciona pegado a la llamada (u.saludar()); al pasarlo suelto se pierde. La Arrow Function nace con this fijado: auto-bind, sin necesidad de .bind(). El precio: es una copia por instancia (cada objeto lleva la suya, no comparte prototype) y su this no es dinámico.

Trampa clásica

Fuera de una clase, la Arrow Function no captura el objeto. const o = { saluda: () => this.nombre } — el this es el ámbito exterior (window en normal, undefined en estricto), no o. La clase es lo que le da el this de la instancia al campo con Arrow Function.

Situación Modo normal Modo estricto

Errores comunes

  • Extraer un método y perder this

    const f = ana.saludar; f(); — al guardar el método en una variable, la llamada ya no tiene objeto delante: this pasa a ser window (regla por defecto). Solución: const f = ana.saludar.bind(ana);

  • Pasar un método a setTimeout

    setTimeout(ana.saludar, 1000); — cuando el temporizador ejecute la función, el objeto ya no está delante: this se pierde. Solución: setTimeout(ana.saludar.bind(ana), 1000); Alternativa: definilo como campo con Arrow Function (auto-bind, sección 05).

  • Olvidar la prioridad

    Cuando se combinan reglas, recuerda el orden: new > explícita > implícita > por defecto. En objeto.metodo.call(otro), gana call: this = otro.

  • Confiar en bind con una Arrow Function

    f.bind(otro) no cambia nada: la Arrow Function ignora la regla explícita, su this ya está fijado al nacer. Si necesitas this dinámico, usa un método normal.

Siguiente paso: TypeScript

TypeScript añade tipos a las clases: implements, abstract y public/private/protected en la firma. Ya tienes la base: this, prototype y new funcionan igual.
